## 1. 守るべき安全ルール(最重要)

1. **毎回の人間の許可が必要なのは mainnet の購入だけ**(D18、創業者の明示)。devnet・テスト用の鍵・スキャン・テスト・ドキュメントは確認なしで進めてよい。
2. **ただし次は、毎回の許可とは別に、実行前に1回だけ創業者へ確認する**: リポジトリの公開(push・リモート作成)、ハッカソンへの提出、署名鍵や承認ファイルの中身の閲覧、実資産の移動。
3. mainnet: 新規の専用ウォレット2つ、予算の上限は合計 約 5 USD(D17)。創業者の既存ウォレットは使わない。実行時の承認が無ければ実行しない。1 回成功したらロックし、再購入しない。
4. 鍵・シード・認証ファイルの中身を、表示・貼り付け・コミットしない。`~/.aab-seller/` は創業者の署名鍵(読まない)。
5. 結果の主張は証拠の強さを超えない(§9)。
6. テストが落ちたまま完了報告しない。ガード(検査)は、鳴る条件を作って「鳴った」ことを観測するまで検証済みと書かない(陽性対照)。
7. git: 既存のコミットを書き換えない。`git stash drop`、`rm -rf` はガードでブロックされる。回避せず、別の方法を使う。

## 2. 全体像(30秒版)

**Ask a Brain**(裏コンセプト Market Harness)= 行き詰まった AI エージェントが、人間が承認した専門家の答えを自分で買う。1 回の Solana トランザクションで、売り手と運営に分割して支払う(売り手 9000 / 運営 1000、合計 0.01 単位、手数料 1000 bps)。「却下=無料」は構造で保証する(見積もりは無料、署名済みで確定した取引だけが回答を解放)。

- 最初の売り手 = 創業者自身(5 つのレッスン)。実運用で使うのは devnet まで。**mainnet の購入は 1 回だけ**(創業者の承認つき、これから)。

## 12. 運用上の注意(失敗から学んだこと)

- Codex のネイティブの MCP ツールは**遅延提供**で、静的なリクエストには出ない。完全な一覧は、`exec` 内の `ALL_TOOLS` を模擬サーバーで実行時に取得して検証する(`docs/evidence/replay/`)。`required=true` を付けないと、MCP の起動失敗が黙って無視される。
- Codex が MCP に送る `_meta`、`initialize` の能力宣言、`usage` の項目は、**実測した形だけ**を許容する厳格な検査にしている。バージョンが変わったら再計測すること。
- ゲートの `gate1-next.sh` は作業用のスクリプトで、リポジトリには入れていない。意味は「障害点を順に注入して再起動」。必要なら `scripts/integration/gate1-live.ts` の使い方(`--help`)を読んで再現する。
- `.gitignore` の `evidence/` は `docs/evidence/` を除外していないが、`!docs/evidence/**` で解除済み。
- 秘密スキャンの許可リスト(`scripts/check/gitleaks.toml`)は**ファイル+完全一致**だけ。値が変わる生成物(`fixtures/chain/payment.json` の token account)は再生成のたびに更新が必要。
- 実機でしか出なかった不具合が多かった(genesis の切り詰め、`transactionIndex`、第2事業者のレート制限、MCP の `_meta`、使用量の項目、循環インポート)。**テストが通っても、実機での確認を省かない**。
