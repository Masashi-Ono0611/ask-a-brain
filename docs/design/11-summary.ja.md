# Ask a Brain — 創業者向け実装要約

2026年10月8日夜・JST。正式な設計は [MASTER](10-master-design.md) です。
既存の決定を最優先し、古い設計と違う点は MASTER の上書き表にまとめました。
以下は実装計画であり、支払い・安全性・評価の実行結果はまだありません。

## 作るもの

サービス名は **Ask a Brain**。裏側の考え方は **Market Harness** です。
これは、AI が専門知識を買う際に、予算・送金先・質問の範囲を制限し、支払いと仕事の結果を確認できる仕組みです。
gbrain の公開スライス（公開を承認した小さな資料集）が最初の市場です。

- 本人が選んだ役立つ5ページから開始し、1スライス最大10ページにします。
- 別の5ページの短い架空教材を使ったデモ掲載先も用意し、本人運営と明記します。
- 2〜3件へ無料確認し、「一方は辞退して無料、もう一方は回答可能」を見せます。
- 回答は審査済みの抜粋。質問は承認済み文面、または選択肢が固定された定型文だけです。
- 別プロセスの broker（購入を検査するプログラム）が上限と送金先を確認し、人間のウォレットが署名します。
- Solana の1取引で売り手と市場へ同時に分配し、確定後に保存済み回答を返します。
- 領収書と「何が役立ったか」を記録します。点数を作らず、独立購入者3人までは「未評価」と表示します。

原資料は無料でダウンロードできます。対価は秘密へのアクセスではなく、必要な助言を選んで適用する手間へのものです。
自己購入はお金が動いた検証であり、需要や利益の証明にはしません。

## 今回切るものと理由

自動署名、生成AIによる回答、クラウド標準配備、大量ページ、数値の評判、外部の有料注文、返金準備金を基本範囲から外します。
1人で鍵・内容・評価・動画まで確認する時間を確保するためです。
自動署名は10月10日正午までに隔離試験と本人の選択が揃う場合だけの追加候補。揃わなければ提出後へ延期します。
クラウドは利用先・金額の承認後だけ。回答生成を追加する場合も、費用と試験を含めて別途設計を改めます。
署名方式と支払い方式は各1つ。x402/Pay.sh（APIの従量支払いの仕組み）は30分だけ調べ、接続の実装は後回しです。

## 絶対に守る線

元の脳の検索、候補選び、非公開の事例調査、書き直しの入力確認は、**本人がローカルで、AIセッションの外で**行います。
ローカルAIにも非公開の入力を渡しません。AIが受け取るのは公開承認済みの文面か件数だけです。
勤務先・顧客・非公開会員・第三者の私的情報は、匿名化や要約をしても販売対象にしません。
秘密鍵は本人だけが作成・管理し、AIや録画に映しません。
配信は隔離したローカル環境で行い、元の脳・自宅フォルダ・鍵へ届かないことを試します。
撤回した内容は支払い後でも返しません。再起動やバックアップ復元でも配信を止め、返金未処理額を残します。
返金は本人の手動操作で、保証や自動処理をうたいません。

領収書をgbrainへ入れる場合は専用領域に「外部の引用資料」として保存します。
悪意の指示を混ぜた試験資料を、保存後に読み直しても勝手な操作が起きないことを確認します。
確認できなければ本文は手元に保存し、gbrainには取引番号などの情報だけを入れます。完全な本文保存は未達と明記します。

## 評価と3分デモ

過去事例は、本人所有の公開gbrain PR（変更提案）・Issue（課題記録）、公開の個人コード置き場、明確に個人用途の出来事から選びます。
公開されていても勤務先由来や他人の文章は無条件で使えません。調査は本人が行い、承認した再現用資料だけを渡します。
10件を目標にしつつ、まず3〜5件で時間を見積もります。実際の少ない件数と、残りの未実施件数をそのまま報告します。
各事例を「助言なし」「同じ資料と選択方法の無料チェックリスト」「有料相談」の3条件で比べます。
無料条件は必須です。同等なら「有料相談の方が役立つ」とは言いません。
結果は件数・分数・実支出で示し、金銭的な損失を防いだとは言いません。過去を振り返った補助効果の検証です。

1. 実際に観測した仕事の失敗と、助言後に変わった操作・結果を見せます。無料条件の結果も隠しません。
2. 許可されていない購入を止め、署名も送金も行われない場面を見せます。
3. 2件への無料確認後、許可された相談を人間が署名し、回答と作業結果を見せます。
4. 同じ取引の2つの送金、領収書、結果の記録を見せます。
5. 「本人同士の送金検証であり、需要の証明ではない」と明示します。

改善が観測できなければ、その結果を使います。架空の成功を実際の結果として撮りません。

## 確認済みと未確認

確認済みの入力は、創業者の決定と、10月8日確認済みの公式ルール資料です。
公式審査は **機能、影響の可能性、新しさ、使いやすさ、オープンソース、事業計画**の6項目です。
提出時はリポジトリ（コードの保管場所）を公開し、利用・改変を許すOSSライセンスを付けます。開発中の非公開とは区別します。
公式終了は **10月13日15:59 JST**。内部の提出目標は **10月12日18:00 JST**です。

実装の動作、隔離、送金、引用の一致、領収書の読み戻し、評価結果は、現時点ではすべて未検証です。
本人の利用歴やページ数は本人申告。貢献数や第三者統計、レビューのモデル名は裏付けなしに宣伝へ使いません。
提出フォームの項目、動画条件、既存コード・AI利用の扱いは公式画面で30分以内の初期確認を行います。

## 日別の本人時間

AIの実装時間は別に28〜34時間の見積もりです。本人だけができる作業はAIの並列実行では短くなりません。

| JST日付 | 本人の集中時間 | 本人の主な作業／AIの主な作業 |
|---|---:|---|
| 10月8日夜 | 0.5時間 | 本人だけで候補件数・空き時間を確認／AIは引き継ぎ |
| 10月9日 | 5時間 | 鍵とテスト資金、ページ・事例、承認／AIは共通形式・購入制限・抜粋回答 |
| 10月10日 | 3.5時間 | 全文審査・署名・評価基準／AIは送金、障害復旧、隔離、撤回試験 |
| 10月11日 | 4時間 | 評価署名・採点、mainnet承認、録画／AIは3条件評価と結果表 |
| 10月12日 | 3時間 | 動画、公開確認、登録・提出／AIは重大修正と再現手順 |
| 10月13日 | 予備2時間まで | 提出トラブル対応のみ。機能追加に使わない |

**Gate 1（送金確認）は10月10日18時**。開発用ネットワークdevnetで1取引の同時分配と失敗・再試行を実測します。
通らなければ有料デモとmainnetを止めます。別の支払い方式や2回送金にすり替えません。
**Gate 2（資料・評価準備）は10月11日10時**。安全な資料、実際の事例数、3条件比較、領収書の保存方法を確認します。
**10月11日正午が削減期限**。追加連携・自動署名→生成回答・ページ拡大→第二売り手の追加作業→画面の装飾→評価の繰り返し・未着手事例→動画装飾の順に止めます。
無料比較と安全試験は削りません。残り時間で必須部分が終わらなければ、不足を明記した小さな無課金デモにします。

## 一番大きいリスク

安全で役立つ資料が少ないこと、本人の審査・署名・動画時間が足りないこと、復旧・撤回の不具合が主なリスクです。
無料チェックリストで同じ結果なら、有料助言の優位性は未証明です。自己送金が成功しても事業の証明にはなりません。
提出後も独立した売り手・購入者が集まらなければ単一売り手の道具へ縮小します。それ自体も無料の道具より役立たなければ商品仮説を見直します。
